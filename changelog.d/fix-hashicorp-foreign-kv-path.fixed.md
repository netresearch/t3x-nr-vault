- The HashiCorp Vault storage adapter no longer overwrites or deletes data it does not own. For a new secret it reads the KV path first and refuses (code `1794400012`, nothing changed) when the path holds anything other than an nr-vault write for the same identifier; a failed row or audit write destroys only a key this call created and puts an adopted one back. Before, a path that already held foreign data received a new version, and a failed audit or row write then deleted the key with all its versions.
