- The columns `tx_nrvault_secret.value_checksum`, `tx_nrvault_audit_log.hash_before` and `tx_nrvault_audit_log.hash_after` change from `char(64)` to `varchar(64)`. Run the database analyzer (Admin Tools > Maintenance > Analyze Database Structure) or `typo3 extension:setup` after the update. On MySQL/MariaDB and SQLite the stored values do not change, but MySQL/MariaDB may rebuild the table to change the column type, and audit writes wait while it runs: on a large audit log, apply the change in a maintenance window. PostgreSQL pads `char` values with spaces: an empty `value_checksum` read back as 64 spaces and failed the consistency check of a secret's cryptographic fields, and empty `hash_before`/`hash_after` values broke audit-chain verification.
