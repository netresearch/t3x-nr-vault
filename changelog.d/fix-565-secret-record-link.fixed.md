- Secrets created through a TCA or FlexForm vault field, a record copy, `vault:migrate-field` or the migration module now store their record link under `metadata`, where the orphan cleanup reads it. Before, the callers passed the link as top-level `store()` options, which the service ignores, so the cleanup never saw these secrets (#565). The migration module writes the same keys as the other callers (`source`, `table`, `field`, `uid`) instead of `originalTable`, `originalColumn` and `originalUid`.
- The orphan cleanup (scheduler task and `vault:cleanup-orphans`) deletes a linked secret only when the linked record is gone and no row of the linked table still holds the identifier, so secrets of published workspace versions, translations sharing a field and copies are kept. Inside a workspace the vault field hooks link the live record, not the workspace version. `vault:cleanup-orphans` now keeps a secret whose table, connection or column it cannot resolve, as the scheduler task already did, and both cleanups accept the same sources, including `flexform_record_copy`.
