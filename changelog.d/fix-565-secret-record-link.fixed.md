- Secrets created through a TCA or FlexForm vault field, a record copy, `vault:migrate-field` or the migration module now store their record link under `metadata`, where the orphan cleanup reads it. Before, the callers passed the link as top-level `store()` options, which the service ignores, so the cleanup never saw these secrets (#565). The migration module writes the same keys as the other callers (`source`, `table`, `field`, `uid`) instead of `originalTable`, `originalColumn` and `originalUid`.
- The orphan cleanup (scheduler task and `vault:cleanup-orphans`) deletes a linked secret once its retention period has passed and no row of the linked table, deleted rows included, holds the identifier in the linked field. Secrets of published workspace versions, translations sharing a field and copies are kept; the secret of a discarded workspace version is removed. Inside a workspace the vault field hooks link the live record, not the workspace version. Columns named by a reserved word are recognised. `vault:cleanup-orphans` keeps a secret whose table, connection or column it cannot resolve, as the scheduler task already did, and lists such secrets after the check. Both cleanups accept the same sources, including `flexform_record_copy`.
- `vault:migrate-field` now replaces the field value with the vault identifier, as its documentation describes. Since UUID identifiers were introduced it left the plaintext in the field and the new secret unreferenced.
- The orphan cleanup never deletes a secret younger than 15 minutes, even with 0 retention days: record copies and the migrations store a secret a moment before they write its identifier into the record. It checks the linked row by primary key first and loads a column's values once per run. Both are fast paths for "held" only: before a secret counts as an orphan, the database itself is asked, so its collation (case, trailing spaces under MySQL's defaults) decides as it does for every lookup that resolves the secret.
- `vault:migrate-field` no longer wraps a value that is the identifier of an existing secret in a new secret (also with `--force`), refuses a column that cannot hold an identifier, reads the field back after the update and deletes the secret it just stored when the field does not hold it, migrates hidden and time-restricted records, and recognises a field named by a reserved word.
