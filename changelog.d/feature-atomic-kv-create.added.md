- `AtomicKvStoreInterface` (extends `KvStoreInterface`) with a create-only `create()`, implemented by the shipped HashiCorp KV client with a KV v2 check-and-set write (`cas=0`). The HashiCorp adapter claims the KV path of a new secret with it, so a key that somebody else creates between the check and the write is refused (code `1794400012`) instead of overwritten, and nothing is destroyed. New exception code `1794400013` for "key exists".
