- `vault:store --metadata` on an existing secret no longer loses a metadata write that another process commits while the command runs: the pairs are merged into the stored map by `VaultService::store()` itself, under the new `mergeMetadata` option, inside the store's own locked transaction on the local storage adapter. With the HashiCorp or AWS adapter the read and the write of one store are still not one transaction (#570, tracked in #576).
