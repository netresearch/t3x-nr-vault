- AWS Secrets Manager adapter: when the registry row write fails after an update of an existing secret or after an adoption of an earlier write, the rollback moves `AWSCURRENT` back to the version the write replaced with a conditional `UpdateSecretVersionStage`, instead of reading the current version and then putting the previous value back. That closes the window between the rollback's version read and its put: a writer that lands there now keeps its value. (A writer already visible to that read was skipped before as well.) A rollback is reported as applied only when a move call succeeded; a failed move writes nothing, and the adapter logs one warning that names the secret and the reason (not applied, unconfirmed, or another writer). Without the new permission `secretsmanager:UpdateSecretVersionStage` the rollback falls back to the old read-then-write and logs a warning. Not covered, unchanged from before: the compensations of a failed audit write (create, update and the valueless completion path), and the rollback of a create, which still deletes a write that lands between the version check and the delete because AWS has no conditional delete (documented in ADR-054) (#567).
