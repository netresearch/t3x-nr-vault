- AWS Secrets Manager adapter: when the registry row write fails after an update or an adoption, and when the audit write fails after a create that adopted an earlier write, the rollback moves `AWSCURRENT` back to the version the write replaced with a conditional `UpdateSecretVersionStage` instead of reading the current version and putting the previous value back. A writer that lands between the write and the rollback now keeps its value; before, the rollback overwrote it. A move that fails for any other reason than a missing permission writes nothing. Without the new permission `secretsmanager:UpdateSecretVersionStage` the rollback falls back to the old read-then-write and logs a warning naming the permission. A create compensation whose rollback throws now reaches the critical "manual reconciliation required" log of `VaultService` instead of ending in a warning. Not covered: the compensation of an update whose audit write failed still writes the previous value back unconditionally, and taking back a create still deletes a write that lands between the version check and the delete, because AWS has no conditional delete (both documented in ADR-054) (#567).
